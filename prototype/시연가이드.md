# HumanProof 발표 시연 가이드

첨부 발표 초안의 핵심 경로를 실제로 클릭할 수 있는 웹 프로토타입입니다. 작업 등록, 이해 과제, 검토자 승인, 파일 검증을 한 번의 시연으로 보여줍니다.

## 시작하기

- 가장 간단한 방법: `HumanProof_프로토타입.html`을 Chrome 또는 Edge로 엽니다. 인터넷 없이도 과제, 승인, 파일 해시 비교가 동작합니다.
- 웹 주소: https://human-approval-minsub-demo.minsub1489.chatgpt.site
- 위 링크는 기존 배포본입니다. 이번 저장소 개선은 로컬 실행본에 반영했으며 사이트 재배포는 하지 않았습니다.
- 웹 주소는 소유자에게만 공개되는 비공개 사이트입니다. 발표자는 로그인한 브라우저에서 사용하세요. 팀원이 함께 체험하려면 HTML 파일을 전달하면 됩니다.
- 실행이 제한되는 환경에서는 아래의 로컬 서버 실행 방법을 사용하세요.

샘플 PDF와 AI 사용 신고가 기본으로 준비되어 있습니다. `새 작업 등록`을 누르면 실제 PDF 또는 샘플을 등록할 수 있습니다. 시연에서는 한 작업을 다루며, 새 작업은 기존 샘플 작업을 대체합니다.

## 5분 시연 순서

| 시간 | 클릭할 화면과 동작 | 발표에서 설명할 내용 |
| --- | --- | --- |
| 0:00–0:40 | 작업 관리에서 PDF v1, AI 신고, SHA-256 확인 | “파일과 채팅으로 흩어졌던 기록을 특정 버전에 연결했습니다.” |
| 0:40–2:00 | `이해 과제 시작` → `3개 샘플 답변 채우기` → 각 탭에서 `답변 제출` | “체크만 하는 대신 선택 이유, 오류 발견, 조건 변경 영향을 설명하게 합니다.” |
| 2:00–3:00 | 상단 `작성자 A`를 `검토자 B`로 전환 → `검토 · 승인` → `샘플 평가 채우기` → 체크리스트 4개 선택 → `v1 승인 · 증명서 발급` | “작성자가 자신을 승인할 수 없습니다. 다른 검토자가 평가 근거를 남깁니다.” |
| 3:00–4:00 | 증명서의 `검증 화면 열기` → `원본 파일 비교` → `1바이트 변경 파일 비교` | “승인 기록은 유효해도, 전달된 파일이 달라지면 파일 검증 결과는 불일치입니다.” |
| 4:00–4:40 | `작업 화면으로` → 역할을 작성자 A로 변경 → `버전 · 이력` → `새 버전 등록` → 샘플로 등록 | “v2는 새 과제와 승인 전 상태로 시작합니다. v1의 승인은 자동으로 옮겨가지 않습니다.” |
| 4:40–5:00 | `승인 증명서`에서 v1 기록과 최신 v2 경고 확인 | “승인 대상과 실제 제출 버전의 혼동을 줄이는 것이 핵심입니다.” |

반복 시연 전에는 `작업 관리`의 `시연 처음부터`를 눌러 최초 상태로 초기화합니다.

## 추가로 보여줄 수 있는 상황

- 자기 승인 차단: 작성자 A 상태로 검토 화면을 열면 평가와 승인이 비활성화됩니다.
- 오류 발견 실패: 검토자의 `주입 오류 미발견 또는 치명 오류 있음`을 선택하면 6점이어도 승인이 차단됩니다.
- 점수 기준: 세 과제 0–2점, 총점 5/6 이상, 치명 오류 없음, 평가 근거, 체크리스트, 최종 검토 메모가 모두 필요합니다.
- 수정 요청: 검토자가 근거를 남기면 이전 검토 회차를 보존하고 현재 점수·메모·체크리스트를 초기화합니다. 작성자가 답변을 고쳐 모두 다시 제출해야 합니다.
- 기여 근거: Chrome 확장 프로그램에서 JSON을 내보내고 `버전 · 이력 → 확장 기여 기록 가져오기`에서 미리보기 후 연결합니다. 검토 범위가 바뀌므로 기존 평가가 초기화되며, 승인된 버전에는 추가할 수 없습니다.
- 승인 철회: 검토자 B로 증명서의 `승인 철회`를 누르고 사유를 입력하면 검증 화면에서 철회 상태를 확인할 수 있습니다.
- 실제 파일 검증: 원본 PDF를 내려받고 검증 화면의 파일 선택으로 다시 비교할 수 있습니다. 20 MB 초과와 PDF 아닌 파일은 차단합니다.
- 감사 기록: `버전 · 이력`의 `체인 확인`으로 이벤트 연결을 확인할 수 있습니다.

## 구현된 부분과 시연 범위

실제 동작하는 기능: PDF 바이트의 SHA-256 계산, 파일 크기·형식 확인, 과제 답변과 확신도, 인간 평가와 승인 차단 조건, 버전별 승인, 증명서 JSON, 인쇄, QR 생성, 파일 일치 비교, 철회, 브라우저 기록 저장과 감사 해시 체인.

시뮬레이션하는 기능: 작성자·검토자 역할 전환, 샘플 평가와 위험도 입력. 실제 계정 인증, 서버 권한 검사, DB·파일 저장소, Ed25519 전자서명, 실시간 공개 검증 서버는 연결하지 않았습니다. 이 프로토타입의 승인 증명서는 인증서나 법적 증명이 아닙니다.

기록은 현재 브라우저에만 저장됩니다. 다른 기기에서 QR을 열면 공개할 수 있는 발급 당시 요약만 표시하며, 현재 효력을 확인했다고 표시하지 않습니다. 답변과 비공개 검토 메모는 QR에 포함하지 않습니다. 브라우저 저장값과 QR 요약은 전자서명되지 않아 변경될 수 있습니다. 실제 운영용 검증에는 서버와 서명 구현이 필요합니다.

저장소는 IndexedDB입니다. 저장 실패 시 승인·감사 기록과 변경 내용을 함께 롤백하고 백업 버튼을 표시합니다. 여러 탭에서 같은 revision을 바꾸면 한 번만 저장되고 충돌한 탭은 최신 기록을 불러옵니다. 손상된 저장값은 자동 초기화하지 않습니다. 초기화 전 복구 화면에서 백업을 받을 수 있습니다.

업로드한 PDF를 바꾸어도 과제는 이 프로젝트의 설계 예시를 사용합니다. 업로드 문서에 맞춘 과제 자동 생성은 구현하지 않았습니다. 위험도와 평가 합격 기준은 기획의 제안값이며 조사 결과가 아닙니다.

발표 초안 7, 13, 17, 18, 20, 31, 32번 슬라이드의 흐름을 우선 반영했습니다. 샘플 파일, 계정과 답변은 시연용입니다.

## 로컬 서버로 실행

터미널에서 이 폴더로 이동한 뒤 다음을 실행합니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 http://127.0.0.1:4173/ 을 엽니다. 종료는 터미널에서 Ctrl+C입니다. localhost QR은 다른 기기에서 접속할 수 없으므로, 휴대폰 QR 시연에는 웹 주소를 사용하세요.

## 수정할 파일

- `dist/index.html`: 페이지 문서와 메타데이터
- `dist/styles.css`: 색상, 레이아웃과 반응형 표시
- `dist/app.js`: 과제 문항, 샘플 답변, 화면과 상태 처리
- `dist/domain.js`: 승인 규칙, 입력 검증, 승인 범위와 감사 무결성 검사
- `dist/repository.js`: IndexedDB와 revision 검사
- `HumanProof_프로토타입.html`: 설치 없이 실행할 수 있도록 위 파일을 합친 버전

저장소 최상위에서 `npm run build`를 실행하면 단독 HTML을 같은 소스로 재생성합니다.

QR 라이브러리: [QRCode.js](https://github.com/davidshimjs/qrcodejs), MIT 라이선스. 라이선스 전문을 `dist/QRCODE-LICENSE.txt`에 포함했습니다.
